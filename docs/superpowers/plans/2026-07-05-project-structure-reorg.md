# Project structure & naming reorg Implementation Plan

**For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Every task is an independently green unit (builds + full suite pass on its own) ending in an `rtk jj commit` step carrying `Plan:` / `Plan-Tasks:` trailers. Tasks are pitched at **contracts, boundaries, invariants, and behaviors** — not prescribed code; the TDD implementer writes the actual moves/bodies.

**Design source:** `docs/superpowers/plans/drafts/2026-07-04-project-structure-and-reorg-design.md` (reviewed, **accepted-with-amendments**). This plan encodes the accepted §3 phased reorg plus the review's amendments. The draft's invariants **I1–I5**, its snapshot/byte contracts, and its cacheability rules are **binding** for implementation: keep the suite green, no `.received.` snapshot re-accepts except where a task explicitly owns a rename. **Amendments 2–8 referenced throughout this plan are enumerated in that draft's "## Accepted amendments (2026-07-05 review)" section at its end — that section OVERRIDES the draft body wherever they conflict, so a subagent opening the draft for context must read the amendments first.** In particular the draft body still shows the *pre-amendment* shapes (shift-group at `namespace Synto` / exception 1c; `Builders/` → `Facades/`; `SymbolMetadataExtensions` folded into `Incremental/`); the amendments section is the authoritative delta.

**Goal:** Make the three source trees feature-first with role-convention globs, align the generator's internal folders to a compiler-phase namespace scheme, kill the `NamespaceShiftRewriter`, and (last) rename the two projects so `dir = assembly = namespace-root` everywhere — all without moving generated bytes, public namespaces, or package identity.

**Architecture:** One linear sequence of 11 tasks (1→11), each an independently green unit. Tasks 1–7 are byte-neutral runtime/authoring work (only `src/Synto`, the shift-group authoring, `architecture.md`, two new guard tests, and the runtime role-folder/glob reorg). Tasks 8–11 rewrite the generator's internal tree, colocate tests, rename both projects, and refresh the KB. `experimental/quote-action-pipeline` — which rewrote `Quoting/` + the pipeline area (the `NodePipeline/` / `ListPipeline/` / `PlanAssembler` shape) — **already merged to main** (its landing commits are ancestors of HEAD, verified 2026-07-05), so there is no branch-timing gate and no rewrite-vs-rewrite collision risk; Phase 2 (Task 8) reorganizes the current on-disk shape directly. The paired project rename is sequenced dead-last among structural work because it rewrites every csproj path.

**Tech Stack:** C# / Roslyn incremental source generators (`netstandard2.0`, Roslyn 5.0 floor), MSBuild (`Directory.Build.targets` / `.props`), xUnit v3 on Microsoft.Testing.Platform (`net10.0`), Verify snapshot testing, jj (Jujutsu) VCS.

## Global Constraints

- **VCS is jj (Jujutsu), not git.** `rtk jj commit` / `rtk jj status`; never `git add`. Every task ends in a commit carrying the `Plan:` / `Plan-Tasks:` trailers shown in its commit step.
- **Green gate (every task, unless the task narrows it):** `rtk dotnet build` (full solution — also proves the self-host/bootstrap chain still builds in lockstep), then the raw MTP test runs:
  `dotnet test --project test/Synto.Test/Synto.Test.csproj`,
  `dotnet test --project test/Synto.Bootstrap.Test/Synto.Bootstrap.Test.csproj`,
  `dotnet test --project test/Synto.Diagnostics.Test/Synto.Diagnostics.Test.csproj`,
  `dotnet test --project examples/Synto.Example.ObjectReader/Synto.Example.ObjectReader.Tests/Synto.Example.ObjectReader.Tests.csproj`.
- **Do NOT route `dotnet test` through `rtk`** (it mangles MTP args). `rtk` is fine for `dotnet build` / `dotnet format`. Scope tests with `-- --filter-method "*Name*"` (never bare `--filter`, never `--filter-class`).
- **Snapshot policy — byte-neutral by default.** Run snapshot work with `$env:DiffEngine_Disabled='true'`. **Zero `.received.` re-accepts** on any task except the one task that explicitly owns a rename (Phase 0 owns the `Template` resource-name preservation; Phase 3 owns snapshot-dir relocation, which must stay byte-identical content). An unexplained output-shape delta is a **finding**, not a rubber stamp. This whole plan is a refactor: no generated bytes, no injected-surface bytes, no public namespaces, and no package identity (`Synto` / `Synto.Core` / `Synto.Diagnostics`) may move (I4/I5).
- **Format gate:** `rtk dotnet format whitespace --verify-no-changes` clean at the end of every task. No git pre-commit hooks (format is enforced by CI + this gate).
- **Invariants I1–I5 (draft §1) are binding:** zero-runtime-dependency consumer surface (I1); netstandard2.0 / Roslyn-5.0 analyzer (I2); single-source-of-truth injection — markers/helpers authored once in `src/Synto`, embedded and rewritten at inject time, never re-declared in the generator (I3); every `Synto.Runtime.*` / `Synto.RuntimeGenerated.*` / `Synto.Helper.*` resource name and its injected bytes survive byte-identically — **unless the owning task explicitly renames it** (Task 2 may retire the shift / `Synto.RuntimeGenerated` prefix) — and generator-internal types never leak into injected/generated output (I4); snapshots pin output shape and package identity (I5).
- **Cacheability unchanged:** no task adds an `IncrementalValueProvider`/`SyntaxProvider` stage or captures `Compilation`/`SemanticModel`/`ISymbol`/`SyntaxNode` into pipeline state. `TrackingNames` files are untouched; the existing terminal cacheability assertions remain the gate.
- **Branch bookmark:** land this work on a dedicated `experimental/project-structure-reorg` bookmark, never directly on `main` until reviewed (large multi-task structural effort; the `implement-plan` workflow's isolated workspace + bookmark-B handles this).
