# Sub-templates + generic `Template<T>` attribute — design

**Status: DESIGN / approved-for-planning.** Pitched at contracts and behaviours, not exact
code. Supersedes the just-shipped "child-template narrow case" generation model for *nested*
`[Template]`s.

## 1. Context — what exists today

- **`[Template(typeof(Target))]` mandates a target.** The attribute has a single constructor
  `TemplateAttribute(Type target)` (`src/Synto/Templating/Definition/TemplateAttribute.cs:12`).
  That `Target` type is the class the generated `public static` factory method is emitted onto.
- **A nested `[Template]` is a _sibling_, not a child, today.** A method-level `[Template]`
  inside a class-level `[Template]` carrier is independently discovered by
  `ForAttributeWithMetadataName` and **generates its own factory** on its own target
  (`ChildTemplateFinder.cs:9-17`; `TemplateFactoryBuilder.cs:146-160`). Nesting only (a) trims
  the child from the parent's quoted output and (b) skips the child's subtree in the parent's
  staging walk so its roots don't leak up. In the shipped `ChildTemplateTest`, both parent and
  child restate `typeof(Factory)`, and the child emits `public static Factory.TypedGetter(...)`.
- **The per-template build is already a reusable, entrypoint-independent unit.**
  `TemplateFactoryBuilder.Build(diagnostics, semanticModel, additionalUsings, templateInfo, options)`
  (`TemplateFactoryBuilder.cs:24`) is keyed on `TemplateInfo` — **not** on
  `GeneratorAttributeSyntaxContext` — and **returns a `MethodDeclarationSyntax?`**. The FAWMN
  context is used only to construct that `TemplateInfo` and read the assembly name
  (`TemplateFactorySourceGenerator.cs:37-58`).

## 2. Goals

1. Replace the single `[Template(typeof(T))]` surface with **two marker attributes**:
   - `TemplateAttribute<T>` (generic) — carries the factory target as `T`. Top-level use.
   - `TemplateAttribute` (non-generic, no target) — sub-template; target pinned by the parent.
   This makes "a sub-template cannot pin its own factory" **structural** — a sub-template simply
   has no way to name a target — backed by two diagnostics for the misuse corners.
2. Change **nested `[Template]` generation** from today's public sibling to a **`private static`
   method emitted onto the parent's factory class**, target pinned from the enclosing carrier,
   generated by **reusing `TemplateFactoryBuilder.Build` verbatim** (parent-driven).

### Non-goals

- No change to top-level template generation (still `public static` on `T`).
- No change to generated *output bytes* of a template body (only the emitted method's visibility
  and the *placement/ownership* of nested ones change).
- No carrier-scoped privacy: `private` means "off the public API surface / class-private", not
  "invisible to sibling carriers targeting the same class" (per approved scope decision).
- Cross-carrier name-collision detection on a shared target is **out of scope** (future work).

## 3. Surface — two attributes

Authored once in `src/Synto/Templating/Definition/` (single source of truth; injected `internal`
by `SurfaceInjectionGenerator` like every marker):

- **`public sealed class TemplateAttribute<T> : Attribute`** — no constructor arg; the target is
  `typeof(T)` recovered from the attribute's type argument. Retains `TemplateOption Options`.
- **`public sealed class TemplateAttribute : Attribute`** — parameterless, no target. Retains
  `TemplateOption Options`. Usable on `Method | Class | Struct` (unchanged `AttributeUsage`).

The old `TemplateAttribute(Type target)` constructor is **removed** (Synto is pre-GA; clean break
over a compat shim).

**Compatibility note (risk):** generic attributes require C# 11. Consumers writing `[Template<T>]`
must compile at `LangVersion >= 11`. Acceptable pre-GA; called out in the migration section.

## 4. Declaration rules + diagnostics

Position × attribute form defines behaviour:

| Position | `[Template<T>]` (generic) | `[Template]` (non-generic) |
|---|---|---|
| **Top-level** (not inside a `[Template]` carrier) | ✅ normal template → `public static` factory on `T` | ❌ **SY-A**: top-level template requires a target |
| **Nested** (inside a `[Template]` carrier) | ❌ **SY-B**: a sub-template must not specify a target | ✅ sub-template → `private static` on the parent's target |

Two new diagnostics (next free ids after SY1028 — propose **SY1029 / SY1030**, finalize at
implementation; both `Synto.Usage`, `Error`, following the existing `TemplateDiagnostics` shape):

- **SY-A "top-level template requires a target"** — a non-generic `[Template]` with no enclosing
  `[Template]` carrier. Message points the author at `[Template<T>]`.
- **SY-B "a sub-template must not specify a target"** — a generic `[Template<T>]` nested inside a
  `[Template]` carrier. Message points the author at bare `[Template]`.

"Nested inside a carrier" = an ancestor type declaration itself carries a `[Template]`/`[Template<T>]`.
The existing `TemplateScope`/carrier machinery already identifies carriers and foreign children
(`TemplateFactoryBuilder.cs:155-160`); reuse it for this check rather than a bespoke walk.

## 5. Generation contract (parent-driven)

### 5.1 Discovery registration

`TemplateFactorySourceGenerator.Initialize` registers **two** `ForAttributeWithMetadataName`
sources (`TemplateFactorySourceGenerator.cs:26`):

- **Generic** `Synto.Templating.TemplateAttribute` + arity — i.e. the ``TemplateAttribute`1``
  metadata name. Transform: if the target node is **nested in a carrier** → report **SY-B** and
  produce no factory; else → build a top-level template (as today) **and** its nested
  sub-templates (§5.2).
- **Non-generic** `Synto.Templating.TemplateAttribute` (arity 0). Transform: if the target node is
  **nested in a carrier** → return `null` (the parent owns it — no independent output); else →
  report **SY-A**. This registration exists purely to catch the top-level-misuse corner; nested
  sub-templates are never independently generated.

### 5.2 Parent builds its children — reuse the existing seam

The recursion attaches at the step that already enumerates children,
`ResolveScopeAndTrimForeignChildren` (`TemplateFactoryBuilder.cs:155`). Today it only trims each
`ctx.Scope.ForeignChildren` from the parent's quoted output. Extend it so that, for each foreign
child, the parent:

1. Constructs a `TemplateInfo` for the child directly — `Source` = the child method node,
   `Target` = **the parent's `Target`** (pinned), `Options` = the child's `[Template].Options`,
   `AttributeSyntax` = the child's `[Template]` (still trimmed). This is a **second construction
   path** on `TemplateInfo` alongside `TemplateInfo.Create(GeneratorAttributeSyntaxContext)`
   (`TemplateInfo.cs:26`) — the generic `Create` reads the target from `AttributeClass.TypeArguments[0]`;
   this path is handed the target. No build logic changes.
2. Calls `TemplateFactoryBuilder.Build(...)` **recursively** with that `TemplateInfo`, getting back
   a `MethodDeclarationSyntax`. Nested-sub-templates-within-sub-templates fall out for free
   (Build calls Build). The child's own staged roots become that method's parameters exactly as a
   sibling's do today; the child's own `ResolveScopeAndTrimForeignChildren` handles its children.
3. Rewrites the returned method's visibility **`public` → `private`** (see §5.3), and collects it
   into a per-build list of "extra members" on the context.

The parent's own factory method is still assembled by `QuoteAndAssemble` as today.

### 5.3 Visibility

Visibility is hardcoded in exactly one place — `QuoteAndAssemble`
(`TemplateFactoryBuilder.cs:944`, `.AddModifiers(Token(PublicKeyword), Token(StaticKeyword))`).
Thread a visibility choice into the build (or post-process the returned method's modifiers): the
top-level factory stays `public static`; a sub-template is emitted `private static`. This is the
only substantive change inside the ~675-LOC build unit.

### 5.4 Document assembly — one document, many methods

`TemplateDocumentBuilder.Build` (`TemplateDocumentBuilder.cs:22`) today takes a
`Func<UsingDirectiveSet, MethodDeclarationSyntax?>` returning **one** method and `AddMembers`es it
(`:38`). Generalize the seam to return **a method list** (parent factory + private sub-template
methods), so:

- `AddMembers(...)` receives all methods (all land on the same target partial class — §2 privacy).
- `FindReferencedHelpers` (`:128`) scans **all** emitted methods, so a helper referenced only by a
  sub-template is still injected (its completeness-by-scanning property is preserved).
- The document file name stays keyed on the **parent's** source identifier
  (`{Target.FullName}.{parentSource.Identifier}.g.cs`, `:103`) — sub-templates no longer produce
  their own `.g.cs`.

## 6. Migration & impact

Mechanical but wide (this is why it is Phase 1):

- **Every `[Template(typeof(X))]` → `[Template<X>]`** across `test/`, examples, the ObjectReader
  dog-food, and any self-host/bootstrap usage in `src/Synto` (verify the bootstrap's own template
  recognition migrates in lockstep — build gate catches divergence).
- **Snapshots re-accept** where (a) a factory's attribute form changed in the *source* under test,
  and (b) a former nested sibling flips `public` → `private` and folds into the parent's `.g.cs`
  (its standalone `.g.cs` disappears). `ChildTemplateTest`'s nested cases change shape: the nested
  `[Template(typeof(Factory))]` becomes bare `[Template]`, `Factory.TypedGetter.g.cs` disappears,
  and `TypedGetter` appears as a `private static` member inside the parent's document. The
  *standalone* (non-nested) getter template variant stays a public sibling.
- **Orphan/collision guards**: `SnapshotOrphanGuardTest` matches by filename and is move-safe;
  `ZeroCollisionTest` / `InjectedSurfaceCompletenessTest` pin the injected surface — adding
  `TemplateAttribute<T>` extends that surface and re-accepts those snapshots once.

## 7. Phasing (each phase independently green)

- **Phase 1 — attribute split + migration.** Author both attributes; remove the `Type` ctor;
  update `TemplateInfo.Create` to read the target from the generic type argument; register both
  FAWMN sources; add **SY-A** / **SY-B**; migrate every consumer/test/snapshot. *Sub-templates
  still generate as today's public siblings at end of Phase 1* — i.e. a nested `[Template]` (now
  targetless) is temporarily resolved to the parent's target but still emitted public/independent,
  OR Phase 1 keeps the sibling path alive behind the new surface. **Gate:** full build + test,
  snapshots re-accepted only for surface/attribute-form changes.
- **Phase 2 — parent-driven private sub-templates.** Attach the recursion at
  `ResolveScopeAndTrimForeignChildren`; thread visibility; generalize `TemplateDocumentBuilder` to
  a method list; stop independent generation of nested non-generic templates. **Gate:** full suite,
  nested sub-templates now `private` and folded into the parent document; no leakage regressions
  (the existing `ChildTemplate_*_DoesNotLeakIntoParentFactory` assertions still hold).
- **Phase 3 — docs/KB.** `refresh-kb`; update `docs/kb/subsystems/templating.md` and the
  `[Template]` glossary/surface entries.

## 8. Open decisions / risks

1. **Phase-1 interim behaviour** (above): does a targetless nested `[Template]` at the end of
   Phase 1 still emit a public sibling (smaller, reversible steps) or does Phase 1 already suppress
   it (fewer intermediate snapshot churns)? Recommend: keep the sibling path alive through Phase 1
   so the phase is a pure surface swap, then delete it in Phase 2.
2. **SY-code numbers** SY1029/SY1030 assume nothing else claims them first; confirm against the
   registry at implementation.
3. **C# 11 floor** for consumers (generic attributes). Acceptable pre-GA; documented.
4. **In-flight branch:** `experimental/quote-action-pipeline` touches `Templating/Quoting/`; this
   design touches `Templating/Pipeline/` (builder, document builder, discovery) and the surface —
   low overlap, but sequence after that branch's merge/abandon if it also moves the pipeline spine.
